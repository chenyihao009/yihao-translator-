# 维护与开发

普通用户不用运行本页的命令，直接下载Release安装包并按[安装教程](INSTALL.md)使用。

## 项目结构

根目录的 `manifest.json`、JS和HTML就是可直接加载的扩展，没有打包工具或运行时依赖。

- `content.js`：YouTube页面中的面板、样式弹窗与字幕层。
- `service-worker.js`：设置、字幕获取调度、下载和浏览器后台入口。
- `source.js`、`capture.js`：YouTube当前可访问字幕的获取。
- `offscreen.*`、`worker.js`：浏览器内部的翻译线程。
- `caption-source.js`：保留JSON3字幕事件顺序，谨慎处理滚动重发与时间估算。
- `numbers.js`：数值等值比较和不确定表达提示。
- `core.js`：分句结构与标点校验、SRT解析/输出等。
- `recovery.js`：宽容恢复可用译文、固定原文分块，质量疑点不阻塞任务。
- `review.js`：审校输入与结果检查，限制原词覆盖并重算字幕时间。
- `store.js`：本地任务、源字幕与请求缓存；源缓存只存raw和metadata，不存API密钥。
- `settings.*`：首次配置和高级排错。
- `help.*`：离线使用教程。
- `subtitle-rules.txt`：初译与审校共用的五条字幕规范。
- `sentence-prompt.txt`、`review-prompt.txt`：初译和独立审校提示词。
- `docs/`：用户与维护者教程；`samples/`：原创教学字幕。

## 本地检查

维护者安装Node.js后，在项目根目录运行：

```text
npm run check
npm test
```

没有npm依赖，不需要 `npm install`。核心测试只使用原创合成字幕和模拟模型响应，不连接模型、不消耗API余额。审校回归应覆盖保留原稿、纠正有依据的问题、拒绝危险修改、审校失败采用初译继续、关闭后不发起审校，以及输出上限有界处理。浏览器界面测试还应手动检查审校进度显示、总开关跨页面同步与持久化、重新开启需手动继续、“显示字幕”只控制显示，以及暗色背景、两个字幕页签、全屏、字号比例和多个标签页的目标选择。

## 重新打包

维护者安装Python3后，在根目录运行：

```text
python scripts/package.py
```

输出在 `dist/`：用户安装ZIP、GitHub源码ZIP和校验值。安装ZIP根目录直接包含清单，不再套 `extension` 子目录。脚本采用文件白名单，不读取API密钥、浏览器资料或私人工作目录。

用户安装扩展不需要Node.js或Python；这些只用于维护者检查与制作发布文件。

## 修改时留意

1. 更新 `manifest.json` 和 `package.json` 中的版本号，以及发布说明。
2. 修改翻译规则或缓存结构时，评估是否需要增加 `core.js` 中的RULE_VERSION，避免把旧结果当成新规则的输出。
3. 不把API Key写入代码、配置、截图或Issue；本地密钥只由用户在扩展设置中输入。
4. 不把完整视频字幕、模型分析或浏览器资料作为测试素材公开；使用原创合成案例。
5. 字幕的句末标点是结构检查，不能证明语义完整。AI自审也可能漏检或误改；数字、快捷键和专业术语仍需对照原文。审校没有发现问题时不强制重写。
6. 使用YouTube未公开稳定的网页/播放器接口，接口变动可能导致获取失败，不承诺覆盖任意视频。

当前没有GitHub Actions自动发布流程，也不会因为上传代码而自动替你创建或发布Release。按[发布教程](PUBLISH_GITHUB.md)在网页操作即可。


## 0.1.7 完成优先与审校

顺序：全文分析（失败可用简易方案）→ 分批初译 → 宽容恢复可用译文 → 独立AI审校 → 采用可用结果 → 发布本批。共享五条质量规范仍保留。

`recoverSegments`只因空译文或不可靠词范围要求恢复。模型英文改写时从原词重建英文；数值、标点或多句疑点只记内部notes。结构修复一次仍失败，则程序生成固定原文块，模型只返回chunk_id与中文；批量JSON失败后按短块单独翻译并分别缓存。不能用空白或原文冒充中文字幕。

合法初译先保存为待审稿。审校严格限制修改覆盖与事实，坏建议保留初译；任何审校失败或长度截断均回用初译继续，不重试审校、不阻塞整片。notes和diagnostic保存在本地供排查，不在普通面板展示；账户、余额、网络及无字幕等需要用户处理的故障仍给出可理解的提示。

规则版本保持 `sentence-v2.4`，复用0.1.6已经完成的进度；请求策略为 `success-v1`，审校策略为 `review-v2`，不复用旧失败请求。后续任何请求前都检查总开关和epoch，不能让回退绕过停止操作。当前只接DeepSeek，其他API暂不增加配置负担。

## 0.1.5 请求策略

分析与翻译的思考模式分开：分析使用一次有界低强度思考及最多一次精简回退；翻译/修复关闭思考。长度截断采用有上限的词窗/预算退避，仍失败则转简单分块，成功批次即时落库。任务按源字幕指纹区分，继续时优先使用该任务保存的同一原始字幕；显式导入不同源会建立另一个任务。请求缓存键包含请求策略、词窗边界、末批标志和预算。修改解析、缓存或退避策略时同步评估规则版本，并保留停止总开关与epoch校验。
