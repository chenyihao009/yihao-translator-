# 字幕翻译与显示规范

本项目用五条共同规范约束初译和AI审校。规范用于改善质量，产品以完成翻译为先。正常流程按完整句意组织；最后的简化回退允许断句不够完美。

## 翻译顺序

1. 获取原语言字幕与时间信息，不使用 YouTube 的中文机翻作为翻译底稿。
2. 先分析整份原字幕，识别主题、语气、专业领域、术语和可能的转写错误，生成本片翻译规则。
3. 结合本片方案和上下文分批翻译，每条字幕对应连续的原文范围。
4. 程序检查原文范围与可用译文；原文显示取自字幕，数值、标点等疑点只作内部记录。
5. 将原文与初译交给DeepSeek独立审校一次，按下面五条规范检查；有依据才修改，没有问题就保留。
6. 程序检查审校建议；建议不可用则保留初译。时间从原词范围计算，最后显示字幕和提供SRT下载。

## 五条规范

1. **意思忠实**：保留否定、条件、事实、数值、单位和快捷键，不添加原文没有的信息。允许等值的中文数字、数量级和可靠的单位换算；转写或含义不确定时记录待核对项，不凭常识改事实。
2. **句意完整**：每条是一句话或意义完整的独立分句，不把下一句话的开头接在上一条末尾。陈述句通常以“。”结尾，疑问、感叹分别用“？”“！”。不能给半句话补上句号就算完成。
3. **术语一致**：结合全文方案、当前上下文和软件界面选择专业译法。同一含义保持一致；软件名称、菜单、命令和快捷键必要时保留英文，不能机械套用不适合当前语境的词表。
4. **中文自然**：表达简洁流畅，保留讲解者的语气和必要的幽默。避免翻译腔、套话、宣传语和无意义扩写。
5. **便于阅读**：长句优先在意义完整处分开，删去译文自身的赘述，不删原文关键信息。不用固定字数强切句子；时间过短或内容过密时记录疑点，不靠改动事实来缩短。

例如，“左边是项目面板，视频、图片都放在这里。”应在同一完整句意内组织；不要生成上一条以“左边是项目面板，”结束、下一条从“视频、图片……”开始的机械断句。相邻两句也不能为了凑长度合并成一条。

## 审校如何收敛

一次审校只检查当前批次，前后文用于理解，不能把前后批次的内容挪进来。允许在当前覆盖范围内合并或拆分，但全部原词必须保持顺序且恰好覆盖一次。时间由程序根据原词重算，不采用模型编写的时间码。

审校没有发现实质问题时直接保留初译，不强制润色。建议若破坏原文覆盖、改变可核对数值或不符合结构要求，程序不采用这份建议，保留原初译并在内部记录疑点。接口失败或截断时也采用初译，继续下一批，不让审校阻塞整片。

不做多轮“再改好一点”的循环。审校默认关闭思考；审校失败不自动重复请求，直接回用初译。审校增加API用量和等待时间，也不能保证找出所有问题。

共享规范见根目录 `subtitle-rules.txt`；初译与审校提示词分别为 `sentence-prompt.txt`、`review-prompt.txt`。程序检查与回退见 `core.js`、`numbers.js`、`review.js` 和 `recovery.js`。格式检查和AI自审通过，都不等于已经由人核对语义。当前也没有人工逐句校对编辑器。

## 自动简化回退

模型改写了返回的英文时，直接用原字幕恢复英文；可用中文继续保留。范围或结构仍不能使用时，先自动修复一次；再失败则由程序划定原文块，模型只翻译中文。批量结构仍不可靠时按短块单独翻译，每块结果缓存。这个最后回退可能切在不够理想的位置，但不漏掉整段原文，也不把英文冒充成中文字幕。

## 时间对应

字幕时间取自原字幕。JSON3 中存在词级起点时优先采用；词尾时间根据后续起点估算。只有 SRT/VTT 句段时间时，句内时间也需要估算。当前不分析音频进行强制对齐，因此可能有少量提前或延后。

滚动字幕按原字幕事件的文字流顺序处理。词时钟重叠冲突时会保持文字顺序并作单调时间修正，标记为估算，不以重新排序单词来修复时钟。

## 默认显示

- 中文主字幕：28px，白色、加粗、有文字投影。
- 原文副字幕：显示在中文下方，字号为中文的 60%，默认不加粗，颜色稍弱。
- 两行共用暗色背景，用户可在“字幕样式”里关闭；关闭背景后文字投影仍然保留。
- “调整字幕样式”分别设置中文与原文的字号或比例、颜色、加粗和投影。修改立即生效，“恢复默认”重置文字样式，背景开关单独保留。
- 全屏时两种字幕同步放大，并保持字号比例。

下载的 SRT 只保存文字和时间，不保存网页中的颜色、投影、字号或背景。其他播放器如何显示，由播放器设置决定。
